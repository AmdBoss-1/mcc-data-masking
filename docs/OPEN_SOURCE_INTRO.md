# AI Local Data Masking Tool · MCC 脱敏工具 —— 开源介绍

> 本文是面向中文读者的完整介绍。快速上手请看仓库根目录的 [README](../README.md)。

## 一、一句话

**把台账交给 AI，不必交出真实数据。**

本机离线运行的数据脱敏／还原工具：源数据脱敏成「可用假值」的副本发给 AI，AI 产物再按本机码本一键换回真值。**码本不上云、全程不联网、遇到不支持的格式直接报错而不静默跳过。**

## 二、要解决的是什么问题

企业想让 AI 帮着分析台账、报表、生产数据，但真实数据里带着客户名、供应商、车牌、手机号、金额。直接外发过不了合规，手工糊数据又会出现三个新问题：

1. **换不回来** —— 糊完的假值留在 AI 报告里，没法对应回真实对象，报告等于废纸；
2. **格式被破坏** —— 车牌不像车牌、手机号不是 11 位，AI 的识别与统计直接失真；
3. **说不清** —— 改了哪些值没有对照可查，出问题无法回溯，审计过不了。

本工具的做法是：**不隐藏数据，而是给数据一份「可逆的替身」。**

## 三、主闭环

```
① mask   源数据 ──▶ 脱敏副本（+ 加密码本，码本留本机）
② 发给 AI 只把脱敏副本发出去
③ unmask  AI 产物 ──▶ 按码本把假值换回真值
```

**关键语义**：第 ③ 步的输入是**任何含假值的文件**，不限于原文件副本 —— AI 新写的 md、重新导出的 xlsx、对方回传的 docx，只要里面是同一套假值，都能换回真值。

## 四、两个入口

| 入口 | 适合 | 说明 |
| :--- | :--- | :--- |
| **命令行** | 批处理、脚本集成、CI | `mask` / `unmask` / `lookup` / `purge` / `serve` |
| **本机网页控制台** | 日常使用、非工程同事 | 拖拽收发、结果卡给出产物与「打开位置」、对照表搜索／反查／导出 |

控制台只绑 `127.0.0.1`（局域网不可达），页面零外链并打进 jar，**断网可用**。

## 五、能力清单

- **格式矩阵**（mask 与 unmask 双向同套读写器）

  | 分组 | 扩展名 | 处理方式 | 可逆 |
  | :--- | :--- | :--- | :--- |
  | OOXML | `.xlsx` `.docx` `.pptx` | POI 读写，run 级保格式替换 | 双向 |
  | OLE 老二进制 | `.xls` `.doc` `.ppt` | HSSF / HWPF / HSLF，写回自验兜底 | 双向（自验不过则出局） |
  | 文本类 | `.csv` `.txt` `.log` `.md` | 正则就地替换 | 双向 |
  | 数据库 | H2 `.mv.db`、SQL dump | 敏感列取值建映射后回写 | 双向 |
  | PDF | `.pdf` | 仅检测，红字报告命中页与类别 | 不替换 |

- **格式保真**：OOXML 文本常被拆成多个 run，工具按段落拼串定位、在匹配边界切 run，只改命中段；`.doc` / `.ppt` 写回后立即重开回读自验，验不过就报错出局，**绝不产坏文件**。
- **规则引擎**：结构化串（手机号／身份证／车牌／邮箱／税号，其中身份证与税号**重算校验位**）、列名命中、名称假值池（组合生成、长度贴原值、无生僻字，**耐抄**）、地址（省／市保留，街道门牌换假）、数值（默认不动，`--jitter` 才 ±3%）、凭据黑名单（**绝不替换，只告警**）。
- **对照与反查**：对照表按新旧排序、本次映射置顶，支持搜索与导出；`lookup` 支持假→真与反向。
- **码本生命周期**：一码本跨文件累积，`--new` 另开新本，`purge` 覆写后删除 —— 还原完就毁，不留后手。

## 六、安全口径

- 码本单文件 `.mccmask`：**AES-256-GCM** 加密，口令经 **PBKDF2-HMAC-SHA256 60 万次**迭代派生。
- 口令**只交互输入**，不落盘、不进环境变量、不进命令行历史。
- 码本默认存 `./maskbook/`，初始化自动写 `.gitignore`；**不上云、不进仓库**。
- **原文件永远只读**；所有产出先写临时文件再原子替换，不留半截文件。
- 服务只绑 `127.0.0.1`；口令只在服务端内存，**刷新页面即锁**，默认 30 分钟空闲自动锁。

## 七、上手

前置：**Java 17 或更高**。

```bash
powershell -File tools\build.ps1     # → dist/mcc-mask.jar（约 30 MB，同目录附 .sha256）

java -jar dist/mcc-mask.jar mask   台账.csv    -o 台账.masked.csv --book mb
java -jar dist/mcc-mask.jar unmask AI报告.md   -o AI报告.真值.md --book mb
java -jar dist/mcc-mask.jar lookup 苏Y·UB8JK   --book mb
java -jar dist/mcc-mask.jar serve  --root D:\台账 --port 8098 --open
java -jar dist/mcc-mask.jar purge  --book mb
```

批量免交互：`--pass-file <口令文件>`（该文件权限请自管，不要提交）。

## 八、已知边界（诚实清单）

一个脱敏工具的可信度，取决于它敢不敢把边界写在明面上。以下是当前版本的真实限制：

1. **自由文本里的人名／公司名不替换** —— 没有列上下文时无从判断，设计如此。走表格列名命中，或该值已在码本里；也可用 `--rules` 扩词表。
2. **PDF 只检测、不替换** —— 逐页扫出敏感串并红字报告命中位置，不改动 PDF 内容。
3. **套件整机包 `.mccbak` 不直读** —— 包内数据是套件自有加密：先复制 `.mv.db`，或在套件内导出 SQL，再交给本工具。
4. **数值默认不扰动** —— 这是特性不是缺陷：不扰动才能让 AI 的汇总跟你的账对得上。
5. **凭据类一律不替换，只告警** —— 命中时红字提示「检测到疑似凭据」，不阻断流程。
6. **无云端能力** —— 没有联网、没有遥测、没有自动更新检查；也**不支持** JSON / XML / SQLite / 图片 OCR。

## 九、质量与验证

- 引擎 49 项 + 网页控制台 22 项 = **71 项测试全绿**。
- **往返一致**：`mask → unmask` 后与源文件**字节完全相同**。
- **零泄漏**：脱敏产物跑敏感正则 + **原值黑名单 grep**，命中即失败。
- **AI 闭环仿真**：脱敏 → 把假值嵌进新的 md / xlsx → 还原 → 与期望真值文档逐字比对。
- 控制台全流程无头浏览器回归 69 项断言；实测截图见 [`docs/verify/`](verify/)（含错口令、不支持格式、刷新即锁三个错误态）。

## 十、适用与不适用

**适合**：需要在「不泄露真实数据」的前提下让 AI（或外部支持人员）分析表格、文档、报表的场景；内网／物理隔离环境；需要可追溯、可还原的数据外发流程。

**不适合**：希望对 PDF 做逐字打码；希望处理图片／扫描件的敏感信息；希望把脱敏当作加密存储手段（本工具是**外发前的替身**，不是加密盘）。
